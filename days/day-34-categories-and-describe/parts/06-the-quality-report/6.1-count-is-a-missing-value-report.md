# 6.1 — `count` is a missing-value report

## One-line answer

The top row of `describe()` is not a formality that tells you how big the table is — it is the
number of values that are actually **there**, so subtracting it from the number of rows gives you,
column by column, exactly how much of the table was never filled in.

---

## The story

Somebody in the flat sits down to add up what the shopping cost over the year.

They have the file. It has a line for every trip, with the item, which part of the shop it came
from, the pack size, the price and how many were needed. They add the price column up and get a
total. The total looks low. Not wildly low — low in the way that makes you count it again rather
than the way that makes you shout.

So they count the lines. Two hundred and forty thousand. That is right; that is a year.

Then somebody else remembers something. There was a stretch in the spring when the till receipts
were going straight into the bin, and whoever was typing that week just left the price box empty
and moved on. The lines are all still there. Every one of them has an item, an aisle and a size. A
few hundred of them simply have nothing where the price should be.

The line count was never going to find that. Two hundred and forty thousand lines is two hundred
and forty thousand lines whether they have prices in them or not. What you need is a different
count: not *how many lines are there*, but **how many of them actually said something**.

---

## The idea in plain language

Two words have to be separate in your head before the rest of this makes sense. A **row** is one
line of the table, and `len(frame)` is the number of them; a row exists whether or not anybody typed
anything into it. A **value** is one filled-in box inside a row. A row can exist and still have an
empty box.

pandas has a word for an empty box: **missing**. A missing number is stored as `NaN`, a special
float that means *there is no number here* and that is not equal to anything, not even itself
([Day 30, 1.2](../../../day-30-missing-data/parts/01-what-missing-means/1.2-nan-the-number-not-equal-to-itself.md)).
Finding those boxes is what `isna()` does
([Day 30, 2.1](../../../day-30-missing-data/parts/02-finding-it/2.1-isna-and-notna.md)), and counting
them per column is the profile you run on every table you are handed
([Day 30, 2.2](../../../day-30-missing-data/parts/02-finding-it/2.2-counting-the-blanks.md)).

Now the point of this part. `describe()` prints eight numbers for every numeric column — `count`,
`mean`, `std`, `min`, the three quartiles and `max`
([5.1](../05-describe/5.1-eight-numbers-for-a-column.md)). Almost everybody reads the seven numbers
underneath and skips the first one, because "count" sounds like it is telling you the size of the
table, which you already know.

It is not. **`count` is the number of values that are present**, not the number of rows. pandas
skips missing values when it counts, the same way it skips them when it takes a mean. So the first
row of `describe()` and `len(frame)` are the same number only when nothing is missing, and every
place they differ is a column with a hole in it — with the size of the hole written out in full.

That makes `describe()` a data-quality report rather than a summary. The report you already print
out of habit at the top of every notebook has been telling you where the gaps are the whole time.
This section is about learning to read it that way: `count` here, `min` and `max` in
[6.2](6.2-min-and-max-are-a-range-check.md), the quartiles in
[6.3](6.3-the-quartiles-and-the-tail.md), and `std` in
[6.4](6.4-the-column-that-never-changes.md).

There is one catch. By default `describe()` only looks at numeric columns and silently leaves every
text column out ([5.3](../05-describe/5.3-include-exclude-and-the-column-left-out.md)). The
missing-value report you read off it covers *some* of your columns, and it never says which ones it
skipped. That is why the version at the end of this part asks the frame directly instead.

## The mechanism

Start on the envelope, with one price missing — the week the receipt went in the bin.

```python
import numpy as np
import pandas as pd

shop = pd.DataFrame(
    {
        "item": pd.Series(["milk", "bread", "eggs", "rice"], dtype="str"),
        "aisle": pd.Series(["dairy", "bakery", "dairy", "dry goods"], dtype="str"),
        "size": pd.Series(["large", "small", "medium", "large"], dtype="str"),
        "price": [1.15, np.nan, 2.60, 3.05],
        "need": [2, 1, 1, 1],
    }
)
print(shop)
print()
print(shop.describe())
print()
print("rows in the frame:", len(shop))
```

**Line by line:**

- `dtype="str"` written out on each text column. pandas 3.0 infers `str` anyway, but stating it is
  the pin (Principle 4), and it is what
  [Day 26, 2.2](../../../day-26-frames-and-copy-on-write/parts/02-the-str-dtype/2.2-str-the-dtype-pandas-3-infers.md)
  established.
- `np.nan` in the middle of a list of ordinary floats. That is how a blank number enters a frame:
  the column stays `float64` and one of its slots holds the not-a-number value.
- `print(shop)` first, so you see the `NaN` with your own eyes before asking a method about it.
- `len(shop)` last. It is the number this whole part compares against, and printing it beside
  `describe()` is the entire technique.

```text
    item      aisle    size  price  need
0   milk      dairy   large   1.15     2
1  bread     bakery   small    NaN     1
2   eggs      dairy  medium   2.60     1
3   rice  dry goods   large   3.05     1

          price  need
count  3.000000  4.00
mean   2.266667  1.25
std    0.992891  0.50
min    1.150000  1.00
25%    1.875000  1.00
50%    2.600000  1.00
75%    2.825000  1.25
max    3.050000  2.00

rows in the frame: 4
```

There it is, in the first row. **`price` says 3. `need` says 4. The frame has 4 rows.** One price is
missing and the report already said so.

Notice something else while it is small enough to see: `count` printed as `3.000000`, not as `3`. A
count is a whole number, so that is odd. It happens because `describe()` returns a **frame**, and a
column of a frame has one dtype
([Day 26, 1.4](../../../day-26-frames-and-copy-on-write/parts/01-the-two-objects/1.4-one-dtype-per-column.md)).
The report's `price` column has to hold `2.266667` as well as the count, so the whole column is
`float64` and the count comes along as a float.

Now the year, with the four things that actually went wrong in it. This builder is the frame every
part of this section uses.

```python
import numpy as np
import pandas as pd

ITEMS = ["bread", "eggs", "milk", "rice"]
AISLES = ["bakery", "dairy", "dry goods"]
SIZES = ["small", "medium", "large"]
BASE = {"bread": 1.40, "eggs": 2.60, "milk": 1.15, "rice": 3.05}


def a_year(n: int = 240_000) -> pd.DataFrame:
    """A year of the flat's shopping, exactly as it should have been typed."""
    rng = np.random.default_rng(34)
    item = rng.choice(ITEMS, n)
    base = np.array([BASE[word] for word in item])
    return pd.DataFrame(
        {
            "item": pd.Series(item, dtype="str"),
            "aisle": pd.Series(rng.choice(AISLES, n), dtype="str"),
            "size": pd.Series(rng.choice(SIZES, n), dtype="str"),
            "price": np.round(base + rng.normal(0.0, 0.15, n), 2),
            "need": rng.integers(1, 4, n),
        }
    )


def a_bad_year(n: int = 240_000) -> pd.DataFrame:
    """The same year, with the four things that actually went wrong."""
    frame = a_year(n)
    rng = np.random.default_rng(3434)
    frame.loc[rng.choice(n, 400, replace=False), "price"] = np.nan
    frame.loc[7, "price"] = frame.loc[7, "price"] * 100
    frame.loc[11, "need"] = -1
    frame["size"] = pd.Series(["large"] * n, dtype="str")
    return frame


bad = a_bad_year()
print(bad.describe())
```

**Line by line:**

- `np.random.default_rng(34)` — the day number as the seed, and the generator object rather than the
  old global functions, so the numbers printed below appear on your machine too
  ([Day 20, 4.2](../../../day-20-arrays-and-dtypes/parts/04-random/4.2-the-seed-is-part-of-the-result.md)).
  **The draws happen in the order the columns are written**, so moving one column changes every
  column after it. That is why this is a function with a fixed body.
- `base + rng.normal(0.0, 0.15, n)` — each item's own price with a small wobble around it, so the
  prices are four clusters rather than one smear. `np.round(..., 2)` because a price with fifteen
  decimal places is not a price.
- `frame.loc[rng.choice(n, 400, replace=False), "price"] = np.nan` — **wound one**, the spring when
  the receipts went in the bin. `replace=False` so it is four hundred *different* rows, and a second
  generator seeded `3434` so that adding a wound never changes which rows the earlier ones hit.
- `frame.loc[7, "price"] = frame.loc[7, "price"] * 100` — **wound two**, one price typed in pence
  instead of pounds. Multiplying the real value by a hundred, rather than typing a number in, is
  what makes it a true mistake and not a staged one. It is
  [6.2](6.2-min-and-max-are-a-range-check.md)'s subject.
- `frame.loc[11, "need"] = -1` — **wound three**, a quantity that cannot exist. Also
  [6.2](6.2-min-and-max-are-a-range-check.md)'s.
- `frame["size"] = pd.Series(["large"] * n, dtype="str")` — **wound four**, the day somebody tried
  to fill in a handful of blank sizes and wrote `large` over the whole column
  ([Day 30, 5.3](../../../day-30-missing-data/parts/05-filling/5.3-ffill-bfill-and-the-order-you-depend-on.md)
  is the family of methods that does this when it is pointed at the wrong axis). It is
  [6.4](6.4-the-column-that-never-changes.md)'s subject.
- `bad.describe()` and nothing else. One method call on a frame with four separate injuries in it.

```text
               price           need
count  239600.000000  240000.000000
mean        2.050695       2.002625
std         0.837564       0.817611
min         0.470000      -1.000000
25%         1.270000       1.000000
50%         2.045000       2.000000
75%         2.820000       3.000000
max       106.000000       3.000000
```

**239 600 against 240 000.** Four hundred prices were never typed, and the first row of the report
says so without being asked. Every other finding on this page is in that printout too, and the rest
of this section is about reading them.

The subtraction, written out:

```python
bad = a_bad_year()
described = bad.describe()

print("rows in the frame :", len(bad))
print(len(bad) - described.loc["count"])
```

**Line by line:**

- `described = bad.describe()` bound to a name, because `describe()` is expensive — it sorts to get
  the quartiles — and calling it twice in one report costs nothing on four rows and a great deal on
  a real table.
- `described.loc["count"]` — `.loc` selects by **label**, and the report's row labels are the
  statistic names, so this gives one Series with a value per described column
  ([Day 28, 1.2](../../../day-28-selection-and-alignment/parts/01-label-and-position/1.2-loc-by-label.md)).
- `len(bad) - described.loc["count"]` — a plain integer minus a Series. pandas broadcasts the
  integer across every entry, so one expression gives the missing count for every described column
  at once.
- The result keeps the name `count`, because subtraction does not rename anything. That is a small
  ugliness worth fixing before anyone else reads the output.

```text
rows in the frame : 240000
price    400.0
need       0.0
Name: count, dtype: float64
```

`400.0`, not `400`. That is the float dtype from earlier, still there.

And now the honest version — asking the frame instead of asking the report, so that no column can
be left out:

```python
bad = a_bad_year()
present = bad.count()
missing = len(bad) - present

report = pd.DataFrame(
    {
        "present": present,
        "missing": missing,
        "share": (missing / len(bad)).round(6),
    }
)
print(report)
```

**Line by line:**

- `bad.count()` — the same statistic `describe()` puts in its top row, straight from the frame. It
  covers **every** column, text ones included, and it comes back as `int64` rather than as a float.
- `missing / len(bad)` — the share rather than the raw count. Four hundred is a big number or a
  tiny one depending on how many rows there are, and a threshold can only be written against a
  share.
- `.round(6)` on the share, so the printed report is readable. Round for display, never for the
  comparison you then make against a limit.
- Building a `DataFrame` out of three Series that share an index lines them up by column name
  automatically — no loop, no zip, no chance of a row landing against the wrong name
  ([Day 28, 4.2](../../../day-28-selection-and-alignment/parts/04-alignment/4.2-alignment-is-automatic.md)).

```text
       present  missing     share
item    240000        0  0.000000
aisle   240000        0  0.000000
size    240000        0  0.000000
price   239600      400  0.001667
need    240000        0  0.000000
```

Five columns, not two. **`describe()` never mentioned `item`, `aisle` or `size` at all**, and if one
of them had been half empty the report would have looked exactly the same.

## In production

**What a professional writes instead of the teaching version.** Not a `print`. A function that
returns findings, with the policy number stated once and passed in:

```python
import pandas as pd

MAX_MISSING_SHARE = 0.01


def missing_report(frame: pd.DataFrame, *, limit: float = MAX_MISSING_SHARE) -> pd.DataFrame:
    """One row per column: how many values are present, how many are not, and whether that passes."""
    rows = len(frame)
    present = frame.count()
    missing = rows - present
    return pd.DataFrame(
        {
            "column": present.index,
            "rows": rows,
            "present": present.to_numpy(),
            "missing": missing.to_numpy(),
            "share": (missing / rows).to_numpy() if rows else 0.0,
            "passed": (missing / rows <= limit).to_numpy() if rows else True,
        }
    )
```

**Line by line:**

- `frame.count()`, not `frame.describe().loc["count"]`. It covers every column, it returns integers,
  and it does not sort anything.
- `limit: float = MAX_MISSING_SHARE` as a **keyword-only** argument, after the `*`. A threshold
  passed positionally is a bare number at the call site that nobody can read.
- `MAX_MISSING_SHARE = 0.01` at module level, not inline. It is a policy, it will be argued about,
  and an argument about a number is easier when the number has a name and one home.
- `present.index` becomes a real `column` column rather than staying the index, so the result can be
  concatenated with findings frames that have different indexes
  ([Day 32, 1.2](../../../day-32-joining-and-reshaping/parts/01-stacking/1.2-the-index-that-came-along.md)).
- `.to_numpy()` on the other three, so pandas does not try to align four Series and surprise you
  when one of them does not line up.
- `if rows else` on both computed columns. An empty frame is a real input — a filter that matched
  nothing produces one — and dividing by zero rows should give a report, not a crash.
- It **returns** a frame instead of printing one, which is the shape
  [7.1](../07-the-module/7.1-the-audit-module.md) uses for `audit()` and what lets a test assert on
  the result.

Run on the corrupted year, it says this:

```text
  column    rows  present  missing     share  passed
0   item  240000   240000        0  0.000000    True
1  aisle  240000   240000        0  0.000000    True
2   size  240000   240000        0  0.000000    True
3  price  240000   239600      400  0.001667    True
4   need  240000   240000        0  0.000000    True
```

**Everything passed.** Four hundred missing prices is 0.001667 of the file and the limit is 0.01, so
the check is green on a column that has a real hole in it. That is not a bug; it is what the policy
number says. Whether 1 % is right for a money column is the conversation this report exists to
start, and a single limit for every column is the first thing to outgrow.

**What changes at scale.** `count()` is one pass over each column and nothing else. On twenty
million rows it took `0.068 s`; `describe()` on the same data took `1.630 s`, because the quartiles
need a sort. Calling `describe()` to get the missing-value report is roughly twenty-four times the
work for one of its eight rows, and on a frame a few hundred columns wide that is the difference
between a check you run on every load and a check you never get round to running.

Better still, on a Parquet file you do not have to read the data at all. The footer records a null
count per column per row group ([Day 27, 3.1](../../../day-27-reading-and-writing/parts/03-parquet/3.1-columns-on-disk-with-types.md)):

```text
$ uv run python -c "
import pyarrow.parquet as pq
group = pq.ParquetFile('bad.parquet').metadata.row_group(0)
for i in range(5):
    col = group.column(i)
    print(f'{col.path_in_schema:6s} nulls {col.statistics.null_count}')
"
```

```text
item   nulls 0
aisle  nulls 0
size   nulls 0
price  nulls 400
need   nulls 0
```

Reading that footer took `0.0007 s`. Reading the whole file took `0.0592 s`. On a table that does
not fit in memory, the footer is the only version of this check you can actually run.

**The failure that only shows with real data.** A daily job asserted that no column was more than
1 % empty, and passed for months. Then an upstream system renamed a field: the old column stopped
arriving, a new all-empty column appeared, and the check still passed — because it only knew the
names it had been given. **A missing-value report has to be built from the frame's own columns and
compared against an expected set of names**, or it only ever checks the columns that were fine
already.

**The review comment a senior engineer leaves.** *"This uses `df.describe().loc['count']` for the
null check. That silently skips every text column, and this frame has six of them. Use `df.count()`
and assert the column names against the schema at the same time — otherwise a column that vanishes
upstream looks identical to a column that is clean."*

**The interview question.** *"What does the `count` row of `describe()` tell you?"* The answer that
shows you have used it: it is the number of non-missing values per column, so `len(df) - count` is
the missing count, which makes `describe()` a data-quality report and not just a summary. Then the
part that shows you have been burned: it only covers the columns `describe()` chose, so a text
column that is entirely empty never appears in the printout at all — and a count that equals
`len(df)` proves nothing on its own, because an empty string and the word `unknown` are both
perfectly present values.
