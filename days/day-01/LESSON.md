## §1 The story

`docs/PINS_DS.md` contains a table of versions. It looks authoritative. It has a date on it. It was
generated by a careful process.

**Do not trust it.**

Here is why, and it is not hypothetical. In January 2026, pandas released version 3.0. It made
Copy-on-Write the only mode. It changed how string columns are typed. Both changes break code that
*looks* correct and *runs* without error — the classic case is `df["a"][mask] = value`, which used to
modify your dataframe and now modifies a temporary copy that is thrown away one microsecond later.
No exception. No warning. Your data is simply unchanged, and you find out three days downstream when
a model trains on values you thought you had fixed.

A pins file written in August tells you what was true in August. Your Day 1 is not August. So the
rule this whole project runs on is: **a version table is evidence, and evidence has to be regenerated
by the person relying on it.**

That is Principle 4 — *nothing floats* — and Principle 14 — *if reality has changed, the plan is
amended first, before any code works around it.*

Today you generate the evidence, compare it to the table, and freeze whatever *today* says.

There is a second, smaller idea in today: **provenance** (Principle 9). Anything that comes into this
repo from outside — a version number, a dataset, a model id — gets a note saying where it came from
and when. Not because it is tidy. Because in four months you will look at a number and need to know
whether it is a decision or an accident.

## §3 Generate the evidence

Copy this into `days/day-01/lab/verify_pins.py`:

```python
"""Re-verify every version in docs/PINS_DS.md against live PyPI. Day 1, Principle 4."""

from __future__ import annotations

import json
import sys
import urllib.request
from datetime import date

PACKAGES = [
    "numpy", "pandas", "scipy", "scikit-learn", "statsmodels",
    "matplotlib", "seaborn", "plotly",
    "sqlalchemy", "psycopg", "pymongo", "streamlit",
    "xgboost", "lightgbm", "shap", "optuna", "mlflow",
    "nltk", "spacy", "gensim",
    "torch", "tensorflow", "keras", "transformers",
    "sentence-transformers", "chromadb", "faiss-cpu",
    "langchain", "langchain-core", "langgraph", "langsmith",
    "mcp", "fastapi", "pydantic", "ruff", "pytest",
]


def latest(package: str, timeout: float = 15.0) -> str:
    """Return the latest non-yanked version of `package` on PyPI."""
    url = f"https://pypi.org/pypi/{package}/json"
    with urllib.request.urlopen(url, timeout=timeout) as response:
        payload = json.load(response)
    return payload["info"]["version"]


def main() -> int:
    print(f"# PyPI check — {date.today().isoformat()}")
    failures = 0
    for package in PACKAGES:
        try:
            print(f"{package:<26} {latest(package)}")
        except Exception as exc:  # noqa: BLE001 - we want the loop to survive one bad name
            print(f"{package:<26} ERROR: {type(exc).__name__}")
            failures += 1
    return 1 if failures else 0


if __name__ == "__main__":
    sys.exit(main())
```

**Line by line:**

- `"""Re-verify …"""` — the module docstring. It says *why* the file exists, not what it does; the
  code already says what it does.
- `from __future__ import annotations` — makes every type annotation a string at runtime. It costs
  nothing and lets you write modern annotation syntax without version anxiety. Put it at the top of
  every module in this project.
- `import urllib.request` — the standard library HTTP client. Used deliberately instead of `requests`
  or `httpx`: **today installs nothing**, and this script must run on a bare 3.12.
- `PACKAGES = [...]` — a module-level constant. Uppercase by convention means "do not reassign this".
- `def latest(package: str, timeout: float = 15.0) -> str:` — annotated parameters and return type.
  You are not required to annotate; you are required to on Day 19 (PY-23), and starting now costs
  nothing.
- `timeout: float = 15.0` — **always** set a timeout on a network call. Without one, a hung server
  hangs your script forever with no error to read.
- `f"https://pypi.org/pypi/{package}/json"` — an f-string; `{package}` is substituted at runtime.
- `with urllib.request.urlopen(...) as response:` — a context manager. The socket is closed when the
  block ends **even if `json.load` raises**. You will write your own context manager on Day 16 (PY-20).
- `payload["info"]["version"]` — PyPI's `info.version` is the latest non-yanked release. This is the
  authoritative answer. A blog post, a tutorial, and a language model's memory are all *not*.
- `def main() -> int:` — returning an exit code rather than calling `sys.exit` inside makes the
  function testable. A function that exits the process cannot be unit-tested.
- `except Exception as exc:` — broad on purpose here: one typo'd package name should not kill the
  whole report. Note the `# noqa` comment telling ruff this is intentional. Broad excepts elsewhere
  in this project will be rejected in review, including by you.
- `f"{package:<26}"` — left-align in a 26-character field, so the output is a readable column.
- `if __name__ == "__main__":` — this block runs when the file is executed directly and **not** when
  it is imported. That is what lets `tests/` import `latest()` without triggering 36 HTTP calls.
- `sys.exit(main())` — a non-zero exit code makes failure visible to CI and to `&&` chains.

Run it:

```bash
uv run python days/day-01/lab/verify_pins.py | tee days/day-01/lab/pins-$(date +%F).txt
```

- `uv run python <file>` — runs inside the project's virtual environment. Never plain `python`;

- `| tee <file>` — print to the terminal **and** write to a file. That file is your evidence

- `$(date +%F)` — command substitution; `date +%F` gives `2026-08-21`, so the filename records when

## §5 `paths.py` — one module that knows where everything is

Copy into `src/setu/paths.py`:

```python
"""Canonical filesystem locations for the Setu project."""

from __future__ import annotations

from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]

SRC = ROOT / "src" / "setu"
DATA = ROOT / "data"
RAW = DATA / "raw"
PROCESSED = DATA / "processed"
DAYS = ROOT / "days"
DOCS = ROOT / "docs"


def ensure_dirs() -> None:
    """Create the data directories if they do not exist. Safe to call repeatedly."""
    for directory in (RAW, PROCESSED):
        directory.mkdir(parents=True, exist_ok=True)
```

**Line by line:**

- `from pathlib import Path` — `pathlib` over string paths, always. `Path` knows about separators, so
  the same code works on Windows and Linux. String concatenation with `/` does not.
- `Path(__file__)` — the path of *this file*.
- `.resolve()` — turn it into an absolute path with symlinks followed. Without this, `parents[...]`
  can point somewhere surprising when the script is launched from another directory.
- `.parents[2]` — walk up two levels. This file is `<root>/src/setu/paths.py`, so `parents[0]` is
  `src/setu`, `parents[1]` is `src`, `parents[2]` is the repo root. **Count the levels yourself now**;
  this is the line people get wrong and then debug for twenty minutes.
- `RAW = DATA / "raw"` — `Path.__truediv__` is overloaded, so `/` joins path components. You will
  implement an operator overload yourself on Day 15 (PY-18) and this is why it matters: it makes a
  library read like the thing it models.
- `def ensure_dirs() -> None:` — a function, not top-level code. **Importing a module must never have
  side effects.** If this ran at import time, `import setu.paths` inside a test would create folders.
- `mkdir(parents=True, exist_ok=True)` — create intermediate directories; do not raise if it already
  exists. The idempotence you built into `./m scaffold` yesterday, in Python form.

## §6 `versions.py` — the frozen record

Copy into `src/setu/versions.py`:

```python
"""The versions this project was pinned against, and a check that reality still agrees."""

from __future__ import annotations

from importlib.metadata import PackageNotFoundError, version

# Filled in on Day 1 from YOUR verify_pins.py run — not from the docs table.
PINNED: dict[str, str] = {
    "python-dotenv": "1.2.3",
    "ruff": "0.16.4",
    "pytest": "9.1.1",
}


def installed(package: str) -> str | None:
    """Return the installed version of `package`, or None if it is not installed."""
    try:
        return version(package)
    except PackageNotFoundError:
        return None


def drift() -> dict[str, tuple[str, str | None]]:
    """Return {package: (pinned, installed)} for every package that does not match."""
    return {
        name: (pinned, installed(name))
        for name, pinned in PINNED.items()
        if installed(name) != pinned
    }
```

**Line by line:**

- `from importlib.metadata import version` — standard library since 3.8. It reads the version of an
  *installed* package from its metadata. No extra dependency, no parsing of `pyproject.toml`.
- `PINNED: dict[str, str]` — an annotated module constant. Lowercase `dict[str, str]` is the modern
  builtin-generic syntax; `typing.Dict` is legacy and is not used in this project.
- `str | None` — the modern union syntax (3.10+), read as "a string, or nothing". `Optional[str]` is
  the older spelling of the same thing.
- `except PackageNotFoundError: return None` — a **narrow** except. Compare with the deliberately
  broad one in §3 and be able to explain why each is right where it is.
- The `drift()` dict comprehension — you will write these properly on Day 9 (PY-09). For now, read it
  as: *for every pinned package, keep it only if what's installed differs from what's pinned.*
- `drift()` returns `{}` when everything matches. An empty dict is falsy, so `if drift():` reads as
  "if anything has drifted". That is why it returns a dict rather than printing.

**Now do the actual work:** replace the three entries in `PINNED` with the packages you have installed
and the versions **your** run reported.

## §7 The tests that must be able to fail

Principle 7: a behaviour is not done until a test can go red. Two tests today.

`tests/test_paths.py`:

```python
from setu import paths


def test_root_is_the_repo_root():
    assert (paths.ROOT / "pyproject.toml").exists()


def test_data_dirs_are_under_root():
    assert paths.RAW.is_relative_to(paths.ROOT)
    assert paths.PROCESSED.is_relative_to(paths.ROOT)


def test_ensure_dirs_is_idempotent(tmp_path, monkeypatch):
    monkeypatch.setattr(paths, "RAW", tmp_path / "raw")
    monkeypatch.setattr(paths, "PROCESSED", tmp_path / "processed")
    paths.ensure_dirs()
    paths.ensure_dirs()  # second call must not raise
    assert (tmp_path / "raw").is_dir()
```

`tests/test_versions.py`:

```python
from setu import versions


def test_no_drift_between_pinned_and_installed():
    assert versions.drift() == {}, f"version drift: {versions.drift()}"


def test_pinned_versions_are_exact():
    for name, pinned in versions.PINNED.items():
        assert pinned[0].isdigit(), f"{name} pin '{pinned}' is not an exact version"
```

**Line by line:**

- `from setu import paths` — this import only works because `src/setu/__init__.py` exists and `uv`
  installed your project in editable mode. If it fails, re-run `uv sync`.
- `test_root_is_the_repo_root` — asserts the `parents[2]` count from §5 is right, by checking for a
  file that only exists at the root. **Change `parents[2]` to `parents[1]` and watch this go red.**
  Do that now. That is what "a test that can fail" means.
- `tmp_path` — a pytest fixture giving a fresh temporary directory per test. Tests never touch your
  real `data/`.
- `monkeypatch.setattr(...)` — temporarily replaces a module attribute for the duration of one test,
  then restores it. This is how you test code that reads globals.
- Calling `ensure_dirs()` twice — the assertion *is* the second call not raising. That is the
  idempotence claim, tested rather than asserted in a comment.
- `assert x == y, "message"` — the second argument is printed on failure. A bare `assert` that fails
  with no message costs you a debugging round-trip.
- `test_no_drift_…` — this one is **live-ish**: it compares your pins to your environment, so it goes
  red the moment someone upgrades a package without updating `PINNED`. That is the point. It is the
  Day-1 version of the Principle-4 tripwire.
- `pinned[0].isdigit()` — catches `">=1.2.3"` or `"latest"` sneaking into the dict. A pin that starts
  with a symbol is not a pin.

Run them:

```bash
uv run python -m pytest -q
```

- `python -m pytest` rather than bare `pytest` — invokes pytest as a module of *this* interpreter,
  which avoids launcher issues on Windows where Application Control blocks `pytest.exe`.
- `-q` — quiet: one dot per test instead of a line each.

## §9 Traps

- **Pinning from `docs/PINS_DS.md` instead of from your own run.** That file is a starting point with
  a date on it. Your run is the evidence. This is the entire lesson.
- **Using `>=` or `~=`.** That is a wish, not a pin. `test_pinned_versions_are_exact` exists to catch it.
- **Getting `parents[2]` wrong** and not noticing because the tests happened to pass from the repo
  root. Run `uv run python -m pytest` from inside `days/` once and confirm it still passes.
- **Silently swapping a package** that has been renamed or yanked. That is a plan amendment
  (Principle 14), not a code change.
- **Letting a major-version bump through "because it probably still works".** pandas 3.0 probably
  still works, right up until `df["a"][mask] = v` quietly does nothing.
- **Deleting the `pins-<date>.txt` evidence file** because it looks like clutter. It is the
  provenance record for every pin in the repo (Principle 9). Commit it.
- **Side effects at import time.** If `ensure_dirs()` ran at module level, importing `paths` in CI
  would create directories on a build agent. Keep imports inert.
